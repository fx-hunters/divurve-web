# Divurve 초기 설정·진단 UX 검수 가이드

## 1. 변경 목적

로그인 후 초기 설정과 위험성향 진단을 한 화면에 한 가지 판단만 보여주는 흐름으로 정리했다. 간편 진단은 초기 설정 안에서 끝내고 홈을 먼저 보여준 뒤 상세 진단을 안내한다. 상세 답변은 대표 위험성향을 바꾸지 않고 자금 상태, 설명 선호, 보유 경험에 맞춘 설명에만 사용한다.

이번 구현은 실제 금융기관 연결이나 진단 저장 API를 추가하지 않는다. 백엔드 세션의 회원·데모 판정과 기존 Swagger 조회 경계는 유지하고, 아직 계약이 없는 데이터는 체험용 fixture와 `sessionStorage`에 격리했다.

## 2. 핵심 사용자 흐름

1. 회원 로그인 또는 회원가입 결과의 `onboarded=false`를 확인한다.
2. `/initial-setup`에서 설명 분야를 선택한다.
3. 체험용 자산을 불러오거나 건너뛴다.
4. Q1~Q3에 한 문항씩 답한다.
5. 간편 결과와 참고 진단 고지를 확인하고 `홈 시작하기`를 누른다.
6. 홈이 먼저 표시된 뒤 상세 진단 안내가 한 번 나타난다.
7. `지금 맞춤 설정하기`를 선택하면 `/diagnosis/detail`에서 Q4~Q6을 진행한다.
8. `나중에 할게요`를 선택하면 `마이페이지 → 의사결정 프로필` 재개 경로를 확인한다.
9. 상세 완료 후 `/mypage/diagnosis`에서 초기 설정 Shell이 없는 읽기 전용 결과를 확인한다.

## 3. 위험성향 표시명 매핑

Q1~Q3 점수는 A=0, B=1, C=2, D=3이며 합계 범위는 0~9점이다.

| 점수 | 내부 값 | 사용자 표시명 |
|---:|---|---|
| 0~2 | `stable` | 안정항로형 |
| 3~4 | `balanced` | 균형항로형 |
| 5~6 | `active` | 적극항로형 |
| 7~9 | `challenger` | 도전항로형 |

서버에서 `challenge`, 과거 `안정형`·`균형형`·`적극형`·`도전형`, 새 항로형 명칭이 들어오는 경우에도 표시 presenter에서 호환한다. 내부 코드와 사용자 표시명은 분리되어 있으며 Planner의 계획 경로 모델과 합치지 않았다.

## 4. Q1~Q6 데이터 역할

| 문항 | 역할 | 대표 점수 반영 |
|---|---|---|
| Q1 | 손실 상황에서의 행동 | 반영 |
| Q2 | 위험과 기대수익의 관계 | 반영 |
| Q3 | 환율 변동에 대한 대응 | 반영 |
| Q4 | 생활비·비상금과 외화 목적자금의 분리 정도 | 미반영, 설명 맥락만 보완 |
| Q5 | 설명 깊이 선호 | 미반영, 설명 수준 설정에 반영 |
| Q6 | 외화·해외자산 보유 경험 | 미반영, 용어와 보충 안내에 반영 |

초기 설정 1단계의 설명 분야도 위험성향 점수에 영향을 주지 않는다. Q4~Q6을 바꾸더라도 Q1~Q3의 총점과 대표 항로형은 그대로 유지된다.

## 5. 연결형 문장 생성 규칙

`diagnosis-presenter.ts`의 순수 함수가 구조화된 답변을 고정 템플릿에 대입한다. 화면 컴포넌트는 문자열을 다시 계산하거나 raw enum을 조합하지 않는다.

구조는 다음 세 문장이다.

1. Q1~Q3 대표 결과: `[행동 요약] [대표 항로형]이에요.`
2. Q4 자금 상태: `외화자산은 [자금 상태]하고 있으며,`
3. Q6 경험과 Q5 설명 수준: `[보유 경험] 앞으로는 [설명 방식] 안내드릴게요.`

6점 적극항로형, Q4 B, Q5 A, Q6 B의 실제 결과는 다음과 같다.

> 변동에도 계획을 이어가는 적극항로형이에요. 외화자산은 생활비와 일부 함께 관리하고 있으며, 관련 경험이 몇 차례 있어 앞으로는 핵심부터 쉽게 안내드릴게요.

대표 공식 유형명은 `적극항로형`이며 `목적자금 혼합형 · 적극항로형`처럼 상세 값을 하나의 복합 유형명으로 만들지 않는다.

## 6. 강조색 적용 기준

- 대표 항로형: `var(--primary)`, 굵기 800
- Q4~Q6 상세 어구: `var(--normal)`, 굵기 750
- 상세 어구 밑줄: `var(--normal-border)`
- 포커스 링: `var(--primary-border)`

Q4, Q5, Q6에 서로 다른 색을 쓰지 않는다. `strong`, semantic `data-segment`, 굵기와 밑줄을 함께 사용해 색상만으로 의미를 구분하지 않는다. 새 리터럴 hex, rgb, hsl 색상은 추가하지 않았다.

## 7. 마이페이지 상태별 표시

| 상태 | 대표 표시 | 주 동작 |
|---|---|---|
| 미측정 | 진단 전 안내 | 간편 진단 시작 |
| 간편 진단 완료 | 대표 항로형과 한 문장 요약 | 상세 진단 시작 |
| 상세 진단 진행 중 | 대표 항로형, 진행 중 배지, 재개 안내 | 첫 미응답 문항부터 이어서 |
| 상세 진단 완료 | 대표 항로형, 기본 요약, Q4~Q6 연결형 문장 | 상세 결과 보기, 다시 진단 |
| 서버 결과만 존재 | 변환 가능한 항로형 또는 기존 진단 결과, 서버 결과 배지 | 간편 진단 다시 하기 |

마이페이지의 기본 설정에는 `finance`, `plain`, `simple` 같은 내부 코드 대신 한국어 표시명을 사용한다. 환전 우대율 API 값, 서버 실효 스프레드, API 설정 같은 개발자용 필드는 사용자 기본 설정에서 제거했다.

## 8. 홈 진입 후 상세 진단 유도

- 간편 결과에서 `홈 시작하기`를 누르면 초기 설정 진행률이 종료된다.
- 홈 콘텐츠가 먼저 렌더링된다.
- 일반 모션 환경에서는 350ms 뒤 하단 sheet 또는 데스크톱 dialog가 나타난다.
- reduced-motion 환경에서는 지연과 진입 애니메이션 없이 즉시 표시된다.
- Curve SVG는 760ms 동안 한 번 그려지고 반복하지 않는다.
- `지금 맞춤 설정하기`는 중복 클릭을 막는다.
- `나중에 할게요`는 마이페이지 재개 경로를 먼저 보여준다.
- 배경, 닫기 버튼, Escape로 닫을 수 있으며 열릴 때 주 CTA로 포커스가 이동하고 닫힐 때 기존 포커스를 복원한다.
- 데모 세션과 간편 진단을 건너뛴 회원에게는 안내를 강제로 표시하지 않는다.

## 9. 데이터 출처와 우선순위

### 기존 API 연결 영역

- 로그인·회원가입 및 세션의 `onboarded`, `isDemo`
- 회원 마이페이지의 프로필, 서버 설정, 서버 위험성향 결과, 알림 조회
- 기존 홈·Planner·X-Ray·Forecast API 경계

### 이번 작업의 임시 영역

- 자산 불러오기: 공용 체험용 fixture, `AssetSource="mock_import"`
- 진단 진행·결과: `sessionStorage`의 `divurve_initial_setup_diagnosis_progress`
- 설명 분야·수준: `sessionStorage`의 `divurve.profile-explanation-preferences.v1`

표시 우선순위는 현재 세션의 설명 선택값 → 진행 중 상세 진단 Q5 → 기존 서버 설정이다. 진단 카드에서는 현재 세션의 진단 상태가 있으면 이를 표시하고, 로컬 상태가 `unmeasured`일 때만 서버 결과를 별도 출처로 표시한다. 임시 값을 서버에 저장됐다고 표현하거나 미지원 API를 호출하지 않는다.

## 11. 데스크톱 수동 검수 순서

1. PowerShell에서 저장소 루트로 이동한다.
2. 의존성이 없다면 `npm install`을 한 번 실행한다. 이번 변경은 새 패키지를 추가하지 않았다.
3. `npm run dev`를 실행하고 Vite가 출력한 주소를 연다.
4. 브라우저 폭을 1440px로 두고 `onboarded=false`인 회원 계정으로 로그인한다.
5. `/initial-setup`에서 한 화면에 한 단계만 보이고 설명 분야 네 가지가 한국어로 표시되는지 확인한다.
6. `자산 불러오기`를 누르고 짧은 로딩 뒤 체험용 자산 요약과 `체험용 데이터` 안내를 확인한다.
7. Q1~Q3에서 C, C, C를 선택해 6점 `적극항로형`이 표시되는지 확인한다.
8. 이전 질문으로 돌아가 답을 바꾼 뒤 결과가 새 점수 구간에 맞게 바뀌는지 확인한다.
9. `홈 시작하기`를 누르고 홈이 먼저 보인 다음 상세 진단 안내가 한 번만 나타나는지 확인한다.
10. Escape로 닫힌 뒤 자동으로 다시 나타나지 않는지 확인한다.
11. 초기 흐름을 다시 준비한 후 안내에서 `나중에 할게요`를 눌러 마이페이지 재개 경로가 표시되는지 확인한다.
12. `지금 맞춤 설정하기`로 Q4 B, Q5 A, Q6 B를 선택한다.
13. 상세 진행률이 `1/3`, `2/3`, `3/3`으로 보이고 초기 설정 `3/3`이 나오지 않는지 확인한다.
14. 상세 결과에서 대표 제목이 `적극항로형`이고 연결형 문장이 예시와 같은 의미인지 확인한다.
15. 마이페이지에서 `상세 진단 완료`, 한국어 설명 분야·수준, 연결형 요약을 확인한다.
16. `상세 결과 보기`를 눌러 사이드바와 앱 레이아웃은 유지되지만 `초기 설정`, `3/3`, `초기 설정 마치기`가 없는지 확인한다.
17. `마이페이지로 돌아가기`, `설정 변경`, `다시 진단하기`를 각각 확인한다.
18. 상세 진단 Q4까지만 답한 뒤 `나중에 이어서`를 누르고 마이페이지에서 Q5부터 재개되는지 확인한다.

## 12. 모바일·접근성 수동 검수 순서

1. 개발자 도구에서 폭 360px과 390px을 각각 확인한다.
2. 초기 설정 제목, 선택 카드, 이전·다음·건너뛰기 CTA가 가로 스크롤 없이 보이는지 확인한다.
3. 선택 카드 전체를 터치할 수 있고 주 CTA의 높이가 충분한지 확인한다.
4. 홈 상세 안내가 하단 sheet로 나타나며 모바일 내비게이션과 버튼을 사용할 수 있는지 확인한다.
5. 결과 문장이 자연스럽게 줄바꿈되고 상세 강조 어구가 잘리지 않는지 확인한다.
6. Tab과 Shift+Tab으로 주요 버튼·선택지·상세 `summary`에 이동하고 `focus-visible`이 보이는지 확인한다.
7. 키보드 Enter 또는 Space로 선택과 CTA가 동작하는지 확인한다.
8. 운영체제 또는 브라우저에서 모션 감소를 켠 뒤 Curve와 sheet가 기다림 없이 최종 상태로 표시되는지 확인한다.
9. 안내 dialog에서 Escape, 배경, 닫기 버튼이 모두 동작하는지 확인한다.

## 13. 예상 결과

- 회원의 초기 설정은 간편 결과까지 완료한 뒤 홈으로 이동한다.
- 데모 사용자는 초기 설정과 상세 진단으로 강제 이동하지 않는다.
- 상세 진단은 대표 항로형과 점수를 유지한다.
- raw enum과 개발자용 API 필드가 사용자 화면에 노출되지 않는다.
- 상세 결과는 초기 설정 입력 화면과 분리된다.
- 브라우저 History와 직접 URL 진입에서 오류가 발생하지 않는다.

## 14. 알려진 제한사항

- 실제 마이데이터 연결과 자산 저장은 없다.
- 초기 설정 완료, 진단 결과, 설명 설정의 영구 저장 API가 없어 현재 브라우저 탭 세션에만 유지된다.
- 세션 종료, 다른 기기, 다른 브라우저에서는 임시 상태가 공유되지 않는다.
- 현재 고정 presenter는 AI 호출을 사용하지 않는다.
- 서버의 `onboarded` 값을 완료 시 갱신하는 계약은 아직 연결되지 않았다.
- 프로덕션 빌드에 기존 500kB 초과 청크 경고가 있다.
- 이번 최종 자동 검증에서는 실제 Chrome 화면을 육안 판정하지 않았으므로 위 데스크톱·모바일 절차를 따라 확인해야 한다.
