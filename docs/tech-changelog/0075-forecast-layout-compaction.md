## 변경 사유 (Why)

전망 화면이 세로로 과하게 늘어나 한 화면에 담기지 않았다.

- **상단 컨트롤 바** — 통화쌍·기간 칩·기준 시각을 `space-between` 으로 벌려 두고, 기간 그룹만 `라벨 / 칩 / 보조 설명` 3단 세로 스택이었다. 컨트롤 자체보다 여백이 커져 바 높이가 100px 대에 이르렀다.
- **하단 3단 그리드** — 그리드 기본값 `align-items: stretch` 때문에 세 카드가 가장 높은 카드에 맞춰 늘어났다. 일정이 9건이면 옆의 전망 동인 카드까지 600px 넘게 길어져, 빈 여백만 남은 카드를 스크롤로 지나가야 했다.
- **모델 성적** — `<details>` 로 접혀 있어 기본 상태에서 값이 하나도 안 보였다. 펼쳐도 `평균 오차율`·`포함률(80%)`·`랜덤워크 대비` 가 각각 무엇을 잰 숫자인지 화면에 설명이 없어, 카드를 열어도 읽히지 않았다.

## 변경 내용 (What)

- 컨트롤 바를 한 줄(`flex-wrap` 허용)로 압축했다. `전망 기간` 라벨을 칩 왼쪽에 붙이고, 보조 설명은 `aria-describedby` 대상만 `.sr-only` 로 남겼다. 칩 문구가 이미 "향후 N일"이라 시각적으로는 중복이지만 보조기술에는 그대로 읽힌다.
- `.forecast-bottom-grid` 를 `layout.css` 에 새로 두고 `align-items: start` 를 줬다. 카드 높이가 서로 끌려가지 않는다.
- 다가오는 일정 목록에 `max-height: 14.5rem` + 세로 스크롤을 두고, 제목 줄에 `N건` 을 붙였다. 다음 항목이 절반쯤 걸치도록 잘라 스크롤이 있다는 사실이 보이게 했다.
- 모델 성적의 `<details>` 접힘을 걷어내고 항상 펼쳐 둔다. 카드 머리에 "무엇을 잰 값인지" 한 문장을 두고, 지표마다 사용자 언어 설명을 한 줄씩 붙였다. `랜덤워크 대비` 는 `단순 기준선 대비` 로 고쳐 부르고 랜덤워크라는 말은 설명문에 남겼다.
- 기준선 대비 개선 폭이 0 이하면 `+` 를 붙이지 않는다. 서버가 음수를 주면 `+-3%` 로 찍히던 표기 결함이 있었다.
- 758줄이던 `forecast-screen.tsx` 를 `cards/` 표현 컴포넌트 다섯으로 갈랐다(AGENTS §7.2 God Component 기준 위반 해소). 화면은 데이터를 받아 조립만 한다.
- `.sr-only` 전역 헬퍼를 `layout.css` 에 추가했다. `display: none` 은 스크린리더도 건너뛰므로 `aria-describedby` 대상에는 쓸 수 없다.

## 영향 / 리스크

- 계산·API 호출은 건드리지 않았다. 표시 레이아웃과 문구만 바뀐다.
- 측정값(1440px 뷰포트, 데모 세션, 일정 9건 기준):

| 대상 | 변경 전 | 변경 후 |
|---|---|---|
| 상단 컨트롤 바 높이 | 3단 세로 스택 | 56px (한 줄) |
| 전망 동인 카드 높이 | 일정 카드에 끌려 늘어남 | 97px (자기 높이) |
| 다가오는 일정 카드 높이 | 항목 수만큼 증가 | 310px (목록만 스크롤) |
| 모델 성적 카드 높이 | 접힘(값 0개 노출) | 357px (지표 3종 + 설명) |

- 기간 보조 설명이 화면에서 사라진다. 문구 자체는 DOM 에 남아 스크린리더에는 읽히고, 테스트가 `.sr-only` 클래스와 `aria-describedby` 연결을 확인한다.
