## 변경 사유 (Why)

저장된 Plan 응답의 `goal.allocatedHoldingAmount`에는 완료 회차의 실행 금액이 이미
포함되지만, 프론트가 완료 금액을 다시 더해 현재 확보액·진행률·Curve 누적액을
과다 표시했다. 데모는 회차 기록과 임시 데모 선택을 React 컴포넌트 로컬 상태에만
두어 상세 화면 이동, 목표 전환, 재마운트 또는 새로고침에서 기록이나 모드가 사라졌다.

이 변경은 백엔드 저장값을 다시 계산하지 않고 저장 Plan 계약을 그대로 해석하며,
데모 진행 상태만 계정 정보와 분리된 `sessionStorage` UI 상태로 보존하기 위해 필요했다.

## 변경 내용 (What)

- 저장 Plan의 현재 확보액은 `allocatedHoldingAmount`를 그대로 사용하고 완료 금액을
  다시 합산하지 않는다.
- 과거 완료 Curve의 시작 금액은 백엔드 구현과 같은
  `allocatedHoldingAmount - 완료 실행 금액 합계`로 복원한다. 응답 값이 스스로
  모순되면 0으로 보정하지 않고 과거 완료 구간을 숨긴 뒤 안내한다.
- 목표 목록, 상단 요약, 진행률, 남은 금액, Curve, 지점 상세와 전체 계획 상세가
  같은 현재 확보액을 사용한다.
- 데모 기록과 적용한 시나리오는 목표별로 세션에 저장한다. 중복 기록은 같은
  회차 금액을 다시 더하지 않는다.
- 회원이 명시적으로 선택한 임시 데모 모드는 사용자가 계정 플래너로 돌아가기 전까지
  세션에서 유지한다. 데모 동작은 Planner 쓰기 API에 연결하지 않는다.
- 완료한 회차는 시나리오 변경 대상으로 다시 표시하지 않고, 실제 날짜·금액 변화가
  있는 미래 구간에만 대체 Curve를 그린다.
- 서버 내부 코드, 유효하지 않은 비용·날짜·회차 값은 사용자 화면에 그대로 노출하지
  않고 명시적인 미제공 안내로 바꾼다.
- 상세 응답의 회차 행 수와 서버 요약 수가 다르면 제공된 행 수와 차이를 함께 표시한다.
  상세 계획의 활성 여부는 조회한 Plan ID와 현재 active Plan ID를 함께 비교한다.
- 회차가 많은 Curve는 현재·선택·다음·일부 간격 지점만 시각 라벨을 표시하고,
  모든 지점의 키보드 접근성과 접근 가능한 이름은 유지한다.

## 영향 / 리스크

백엔드 `divurve-api`의 읽기 전용 확인 기준은
`21f72c1fd5aa48de95eb1e1c851a93d663986a7a`이다.
`PlanController.storedGoalSummary`가 저장 Plan에서 기본 배정액에 완료 실행액을 더한 값을
`allocatedHoldingAmount`로 반환한다. 프론트 generated 파일과 백엔드는 수정하지 않았다.

| 사례 | 변경 전 표시 | 변경 후 표시 |
|---|---:|---:|
| 저장 Plan: 초기 25 USD + 완료 10 USD | 45 USD | 35 USD |
| 미국 데모: 초기 1,260 USD + 145 USD 기록 | 상단 1,260 USD·42% 잔존 | 1,405 USD·약 47%, 남은 1,595 USD |
| 일본 데모: 초기 40,000 JPY + 35,000 JPY 기록 | 상단 40,000 JPY·22% 잔존 | 75,000 JPY·약 42%, 남은 105,000 JPY |

- `sessionStorage`에는 데모 목표 ID, 기록 회차, 적용한 데모 시나리오와 명시적 데모
  보기 여부만 저장한다. 토큰이나 실제 계정 데이터는 저장하지 않는다.
- 개발 중 HMR이 화면을 재마운트한 정황은 실행 로그가 없어 확정할 수 없다. 다만 같은
  재마운트 경로에서 상태가 유실되던 코드는 테스트로 재현하고 수정했다.
- 회차 완료 응답 자체의 `remainingAmount` 계산은 백엔드가 목표 기본 배정액을 반영하는지
  별도 확인이 필요하다. 화면은 완료 성공 뒤 active Plan을 재조회한 값을 사용한다.
