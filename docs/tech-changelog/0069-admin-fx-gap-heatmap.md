## 변경 사유 (Why)

백엔드에는 결측 조회(`GET /admin/fx-rates/gaps`)와 백필(`POST /admin/fx-rates/backfill`)이
있었지만 보는 화면이 없었다. 숫자 목록으로는 "어디가 어떻게 빠졌는지"가 읽히지 않고,
빠진 구간을 확인한 뒤 다시 받으려면 다른 도구로 옮겨 가야 했다.

**보는 것과 조치를 한 화면에 두는 것**이 목적이다. 빠진 구간을 누르면 그 구간만 다시 받는다.

## 변경 내용 (What)

- `admin-fx-gap-presenter.ts` — 결측 구간을 띠 위 자리로 옮기는 순수 계산
- `admin-fx-gap-heatmap.tsx` — #93이 세운 껍데기를 채웠다. 통화쌍별 띠 + 구간 클릭 → 백필
- 기간 필터, 백필 결과 요약(채운 날·고시 부재 확정·실패 사유·남은 구간)

### 날짜 칸 격자를 쓰지 않은 이유

이슈 본문은 "가로 날짜 × 세로 통화쌍 히트맵"이었는데 **비율 띠**로 바꿨다.

서버가 주는 것은 날짜 한 칸씩이 아니라 **빠진 구간**(`from`~`to`)과 영업일 수다. 칸 격자를
그리려면 어느 날이 영업일인지 알아야 하는데, 그 달력은 서버가 쥐고 있다 — 고시가 없는 날은
`fx_rate_absences`에 부재로 확정돼 커버리지에 포함된다. 프론트에서 주말을 세어 칸을 만들면
**공휴일이 '보유'로 칠해져 사실과 달라진다.** AGENTS.md 1장이 금지하는 재구현이다.

그래서 조회 구간 전체를 100%로 두고 빠진 구간이 차지하는 자리만 그대로 옮긴다. 서버가 준
값만 쓰고 아무것도 세지 않는다. 읽히는 모양은 히트맵과 같고 사실과 어긋나지 않는다.

### 확인 방식

`window.confirm` 대신 인라인 확인 패널을 쓴다. 무엇을 어느 구간에서 다시 받는지 문장으로
보여준 뒤 누르게 한다 — 브라우저 모달은 대상이 무엇인지 보여주지 못한다.

## 영향 / 리스크

백필은 **전체 재적재가 아니라 빠진 구간만** 다시 받는다. 화면에도 그렇게 적었다.
같은 구간을 다시 눌러도 서버가 받지 못한 날은 고시 부재로 확정돼 결과가 계속 줄어든다.

계산에 영향 없음 — 커버리지 비율·영업일 수는 모두 서버 값을 그대로 쓴다.

색만으로 결측을 구분하지 않도록 사선 무늬와 텍스트 라벨을 함께 준다.
