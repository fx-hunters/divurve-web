## 변경 사유 (Why)

백엔드가 무료 호스팅 인스턴스 위에 있어 일정 시간 요청이 없으면 절전 상태로
내려간다. 이 상태에서 첫 API 요청은 인스턴스가 깨어날 때까지 응답을 붙들고
있으므로, 화면에서는 스피너만 도는 무한 로딩처럼 보인다. 사용자는 앱이 멈췄다고
판단하고 새로고침을 반복하는데, 그때마다 기다린 시간이 버려진다.

기다리면 응답이 온다는 사실을 화면이 알려 주면 이 오해가 사라진다. 계산이나
재시도 로직을 더하지 않고, 지연 사실만 알리는 안내 배너를 택했다.

## 변경 내용 (What)

- `api/cold-start-notice.ts` 추가. 리액트 밖에 두는 작은 알림 스토어다. 켜기·구독만
  있고 끄기는 없다. 새로고침하면 모듈 상태와 함께 사라진다.
- `api/client.ts`의 요청 경로에 지연 감지를 붙였다. 응답이 임계 시간(4초)을 넘기거나
  연결이 끊기면 알림을 켠다. 요청을 중단(abort)하지는 않는다. 깨어난 뒤 도착하는
  응답을 그대로 받아야 하기 때문이다.
- `hooks/use-cold-start-notice.ts`(`useSyncExternalStore`)와
  `components/common/cold-start-banner.tsx` 추가. 배너는 `app/root.tsx`에 붙여
  사용자 앱과 관리자 콘솔 양쪽에서 뜬다.
- 배너는 문서 흐름 맨 앞에 놓여 화면을 아래로 민다. 밀린 높이를 스스로 재서
  `--cold-start-banner-height` 토큰에 적고, 화면 한 판을 채우던 `100vh` 자리를
  새 토큰 `--viewport-height`(= `100vh - 배너 높이`)로 바꿨다. 대상은 앱 셸·사이드바·
  랜딩·인증·초기 설정·관리자 셸이다.

## 영향 / 리스크

- 계산·수치 변경 없음. API 요청/응답 계약도 그대로다.
- 배너가 뜨는 동안 화면 높이가 배너 높이만큼 줄어든다. 데스크톱 46px, 모바일 80px을
  실측했다. 전체 화면 요소가 `--viewport-height`를 쓰므로 세로 스크롤바가 새로 생기지
  않는다.
- 임계 시간 4초는 정상 응답과 절전 기동을 가르는 값이다. 짧게 잡으면 평소 느린
  요청에도 배너가 뜨고, 길게 잡으면 안내가 늦다. 조정은 `COLD_START_THRESHOLD_MS`
  한 곳에서 한다.
- 연결 자체가 끊긴 경우(네트워크 단절)에도 같은 배너가 뜬다. 문구가 "기다려 달라"에
  머물러 있어 두 상황 모두에서 어긋나지 않는다.

## 롤백 방법

이 변경은 한 커밋에 모여 있다. 되돌리려면 해당 커밋을 revert 한다. 배너만 끄고
싶으면 `app/root.tsx`에서 `<ColdStartBanner />`를 지운다. 토큰(`--viewport-height`)은
배너가 없으면 `100vh`와 같은 값이므로 그대로 두어도 된다.
