## 변경 사유 (Why)

최신 develop은 목표별 URL·계획 설정·이력·편집과 부분 로딩 화면을 추가했다.
기존 수정 브랜치의 단일 화면 콜백을 그대로 덮으면 상세 복귀와 명시적 데모 선택,
목표별 완료 기록 보존이 사라질 수 있어 두 동작을 결합했다.

## 변경 내용 (What)

- 최신 목표·계획 계약과 URL navigation 구조를 유지한다. 과거 detailRoute props와
  테스트를 새 source/target 구조로 옮기며 기록·복귀에 대한 검증 의미는 유지한다.
- 데모 선택은 명시적으로 종료하기 전까지 보존한다. 늦은 API 경로를 데모 목표 ID로
  해석하지 않으며, 계정 복귀 버튼을 눌러야 API 화면으로 전환한다.
- 목표를 바꿔도 demoProgress의 목표별 완료 sequence와 적용 상황을 초기화하지 않는다.
- 새 계획 요약 presenter를 재사용하면서 내부 예산 코드·경고를 그대로 노출하지 않는
  기존 표시 규칙을 옮겼다. 현재 확보액에 완료액을 다시 더하지 않는다.
- API client의 삭제 응답 허용과 주소 설정 오류 구분은 각각 기존 단일 경계에 유지한다.
  보조 X-Ray 조회 오류, 인증 갱신, create/apply 분리도 보존한다.
- develop의 0076 문서와 순번이 겹친 기존 후속 검수 기록은 0079로 이동했다.

## 영향 / 리스크

계산 엔진·backend·API 생성 코드를 변경하지 않는다. 팀원 기능은 별도로 재구현하지
않으며 Forecast·Home·X-Ray·관리자 변경은 develop의 통합 결과를 유지한다.

## 롤백 방법

배포에서 중대한 회귀가 확인되면 검수 쓰기를 중지하고 배포 담당자가 이전 정상
배포를 복원한다. Git 변경 취소는 해당 develop PR merge commit을 부모 develop
기준으로 revert하는 새 커밋으로 처리한다. 공유 이력을 reset/force push하지 않는다.
Render 제어 권한과 배포 식별자는 별도 확인 대상이다.
