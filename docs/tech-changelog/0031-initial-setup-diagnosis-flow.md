## 변경 사유 (Why)

로그인 후 초기 설정이 직접 자산 입력과 진단 placeholder에 머물러 있어 사용자가 실제 흐름을 끝까지 진행하기 어려웠다. 초기 설정 안에 상세 진단까지 이어 붙인 구조는 홈 진입을 늦추고, 마이페이지의 결과 보기에서도 초기 설정 Shell을 다시 보여주는 문제가 있었다. 위험성향 이름과 상세 답변도 하나의 유형처럼 단순 연결되어 각 데이터의 역할을 오해할 수 있었다.

현재 Swagger 계약에는 초기 설정 완료, 마이데이터 자산 불러오기, 진단 진행·결과 저장 API가 없다. 설명 설정 필드는 서버 설정 계약에 있지만 초기 설정·진단 완료와의 영속화 정책이 확정되지 않았다. 따라서 존재하지 않는 계약을 추정하지 않고 회원·데모 세션 판정은 기존 백엔드 세션에 맡긴 채, 이번 프로토타입의 입력과 진단 상태만 명시적인 브라우저 임시 저장 모듈로 격리했다.

## 변경 내용 (What)

- 초기 설정을 설명 분야 → 체험용 자산 불러오기 → Q1~Q3 간편 진단 → 간편 결과 → 홈 시작 순서로 구성했다.
- 간편 결과 이후 홈을 먼저 렌더링하고, 350ms 뒤 Curve 모티프를 사용한 상세 진단 안내를 한 번 표시한다. reduced-motion 환경에서는 지연과 진입 애니메이션을 제거한다.
- 상세 진단은 `/diagnosis/detail`에서 별도 `1/3`~`3/3` 진행률로 표시하며, 이탈하면 첫 미응답 문항부터 이어진다.
- 사용자 표시명을 안정항로형·균형항로형·적극항로형·도전항로형으로 통일했다. 내부 `RiskProfileKind`와 서버 문자열 호환 매핑은 별도로 유지한다.
- Q4 자금 상태, Q5 설명 선호, Q6 보유 경험을 구조화된 값으로 보존하면서 결정론적 presenter가 자연어 문장을 만든다. Q4~Q6은 대표 항로형과 점수를 변경하지 않는다.
- 자연어 결과에서 대표 항로형은 `--primary`, 상세 맥락은 `--normal`과 굵기·밑줄로 구분해 색상에만 의존하지 않도록 했다.
- 마이페이지 의사결정 프로필을 미측정, 간편 완료, 상세 진행 중, 상세 완료, 서버 결과만 존재 상태로 나눴다.
- `/mypage/diagnosis` 읽기 전용 결과 화면을 추가해 초기 설정 헤더·진행률·완료 CTA 없이 결과를 확인하고 마이페이지 복귀, 설정 변경, 재진단을 수행할 수 있게 했다.
- 설명 분야와 설명 수준은 내부 코드를 노출하지 않고 한국어 표시명으로 보여준다. 현재 세션의 선택값을 우선하고, 값이 없을 때만 기존 서버 설정을 표시한다.
- 마이페이지에서 개발자용 환전 우대율·실효 스프레드 입력 및 raw enum 노출을 제거했다. 기존 계산 계약과 API 응답 타입은 변경하지 않았다.
- 초기 설정 자산 불러오기 fixture를 실제 X-Ray API 흐름과 분리해 출처가 섞이지 않게 했다.

## 위험성향 계산 규칙

Q1~Q3만 A=0, B=1, C=2, D=3으로 합산한다.

| 총점 | 내부 의미 | 사용자 표시명 |
|---:|---|---|
| 0~2 | stable | 안정항로형 |
| 3~4 | balanced | 균형항로형 |
| 5~6 | active | 적극항로형 |
| 7~9 | challenger | 도전항로형 |

- Q4는 생활자금과 외화 목적자금의 분리 정도를 설명한다.
- Q5는 설명 수준 설정값을 정한다.
- Q6는 용어와 보충 안내의 맥락을 정한다.
- 설명 분야와 Q4~Q6은 Q1~Q3 점수 및 대표 항로형을 변경하지 않는다.
- 이 결과는 금융회사의 표준 적합성 진단이 아닌 MVP 참고 진단이다.

## 데이터 저장 및 API 경계

- 인증 후 초기 설정 분기는 기존 `post-auth-routing`과 백엔드 세션의 `onboarded`, `isDemo` 값만 사용한다.
- 자산 불러오기는 `AssetSource: "mock_import"`인 체험용 fixture다. 금융기관이나 마이데이터 연결로 표현하지 않는다.
- 진단 상태는 `sessionStorage`의 `divurve_initial_setup_diagnosis_progress`에 저장한다.
- 설명 분야·수준은 `sessionStorage`의 `divurve.profile-explanation-preferences.v1`에 저장한다.
- 현재 세션의 값이 없으면 마이페이지의 기존 서버 설정을 표시하지만, 두 출처를 서버에 저장된 하나의 값처럼 취급하지 않는다.
- 기능 구현에서 `src/api/generated/**`, Swagger 계약, 패키지 파일, Planner 로더와 계산 로직을 손으로 수정하지 않았다. 이후 develop 동기화로 생성 API의 최신 정본을 그대로 가져왔다.

## 영향 / 리스크

- 브라우저 세션을 닫으면 진단 진행과 설명 설정이 사라지며 다른 브라우저·기기와 동기화되지 않는다.
- 자산 요약은 체험용 fixture이므로 실제 보유 자산과 일치하지 않는다.
- 서버 결과만 존재할 때는 서버 출처를 구분하고, 현재 세션의 상세 답변을 임의로 합성하지 않는다.
- 초기 설정 완료 및 진단 결과를 영구 저장하는 백엔드 계약이 추가되기 전까지 `onboarded` 서버 상태 자체는 이번 화면에서 갱신하지 않는다.
- 전체 프로덕션 번들은 빌드되지만 기존 500kB 초과 청크 경고가 유지된다.
