## 변경 사유 (Why)

#73으로 고변동성 일정 신호를 헤드라인 칩으로 올렸지만, **경제 일정 카드 본체는 여전히 첫 화면 밖**(y=850~1280)이었다. "주의 필요"가 붙은 정보가 스크롤 뒤에 있으면 알림 구실을 못 한다.

다시 재보니 **지금 자리에 두는 한 방법이 없었다.**

| | |
|---|---|
| 첫 화면 가시 영역 | 785px |
| 본문 시작 | y = 237 |
| 일정 카드가 다 보이려면 본문 행이 | 94px 이하 |
| 일정 카드가 시작이라도 보이려면 | 524px 이하 |
| 실제 본문 행 | **597px** ('내 외화 현황' 412 + '내 목표' 161 + 간격 24) |

'내 외화 현황' 하나가 412px이라 본문 행을 524px 아래로 내릴 수 없다. 그래서 옮겼다.

430px 카드를 일정 칩 가로줄로 압축해 헤드라인 바로 아래 전폭 띠로 놓았다. **헤드라인 칩(#73)은 함께 제거했다** — 바로 아래에 같은 일정이 더 자세히 놓이므로 중복이고, 빼면 헤드라인이 117px → 75px로 돌아온다. 되돌린 것이 아니라 신호를 놓을 더 나은 자리를 찾은 것이다.

## 변경 내용 (What)

- `attention-banner.tsx`: 카드 → 전폭 띠. 인라인 스타일을 전부 `attention-banner.css`로 옮겼다(§6).
- **표제를 "주의 필요" → "경제 일정"으로 바꾸고 국면 배지를 뺐다.** 아래 "국면 배지를 뺀 이유" 참고.
- **'환율 범위 확인하기' 링크를 카드 우상단(헤더)으로 옮겼다.** 칩 줄과 같은 줄에 두면 칩이 쓸 수 있는 폭을 뺏고, 칩이 스크롤될 때 링크와 붙어 읽혔다.
- 칩 줄은 한 줄에 두고 넘치면 가로로 민다. 오른쪽 끝에 `mask-image` 로 흐림을 줘 "더 있다"를 알린다. **일정이 늘어도 띠 높이가 자라지 않는다** — 자라면 그만큼 아래 카드가 첫 화면 밖으로 밀린다.
- **스크롤바를 직접 그린다**(`::-webkit-scrollbar`, 두께 0.375rem, 둥근 thumb). 칩에 `margin-bottom: 0.75rem` 을 줘 스크롤바가 놓일 빈 띠를 만들었다 — 스크롤바가 칩을 가리지 않는다(칩 하단 34px, 스크롤바 46~52px).
- 표준 속성 `scrollbar-width` 는 `@supports not selector(::-webkit-scrollbar)` 안에만 둔다. 이 속성이 있으면 Chrome 이 `::-webkit-scrollbar` 규칙을 무시하므로, 모르는 브라우저(Firefox)에서만 켠다.
- `home-dashboard.css` / `home-dashboard-view.tsx`: 배치를 `3 / 5 / 1 4 / 1 2` 로. DOM 순서(=모바일 읽기 순서)도 핵심 → 일정 → 시장 → 목표 → 현황.
- 헤드라인 칩 제거: `today-headline-card` 의 `upcomingEvents`, `home-presenter` 의 `toHeadlineEvents`·`toShortDateLabel`, `UpcomingEventItem.shortDateLabel`, 관련 CSS·테스트.
- `AttentionData` 에서 `regimeLabel`·`tone` 제거(§7 보이스카웃 — 렌더하지 않는 값은 들고 있지 않는다).

### 국면 배지를 뺀 이유

띠에 `[주의 필요] [정상]` 이 나란히 보여서, 표제와 배지가 서로 어긋나 읽혔다. 표제가 고정 문자열이라 국면이 무엇이든 "주의 필요"라고 단정했기 때문이다.

배지 쪽은 더 근본적인 문제가 있었다. 백엔드를 확인하니 두 값이 **같은 출처**다.

```java
// HomeSummaryService.java
private TodayView resolveToday(MarketRegimeView regime, ...) {
    return new TodayView(headlineCode, regime.badge());   // today.badge
}
private AttentionView resolveAttention(MarketRegimeView regime) {
    return new AttentionView(regime.badge(), upcoming);   // attention.regime_badge
}
```

같은 `regime` 을 받아 같은 `regime.badge()` 를 넣는다. 즉 **우연이 아니라 구조적으로 항상 같은 값**이다. 실서버 확인에서도 둘 다 `normal` 이었다. 바로 위 '오늘의 핵심' 띠가 24px 위에 늘 떠 있으므로, 같은 글자를 두 번 보여줄 이유가 없다.

표제는 상태를 단정하지 않고 내용을 가리키는 "경제 일정"으로 바꿨다. 국면 신호는 '오늘의 핵심'이, 개별 일정의 심각도는 칩의 고변동성/중변동성 배지가 계속 담당한다 — 정보 손실이 없다.

**정보 손실 없음** — 카드가 보여주던 모든 일정과 심각도 배지, 범위 링크가 띠에 그대로 있다. 넘치는 것은 감추지 않고 가로로 민다. 뺀 것은 위에 이미 있는 국면 배지 하나뿐이다.

**남는 것** — 시장 카드 하단(951)은 여전히 첫 화면(785) 아래다. 785px 안에 네 덩이를 다 넣을 수는 없고, 잘려도 이어지는 것이 자연스러운 쪽을 아래로 보냈다.
