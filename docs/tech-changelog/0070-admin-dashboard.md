## 변경 사유 (Why)

관리자 콘솔에 진입 화면이 없어 운영 상태를 보려면 화면 여섯 개를 차례로 눌러야 했다.
#93이 `/admin` 에 대시보드 자리를 만들어 두었고, 여기에 내용을 채운다.

**백엔드 신규 작업 없이** 기존 API 만으로 끝나는 카드 셋만 다룬다. 가입자 지표는 신규 API 가
필요해 #94 로 갈랐다 — 카드 하나 때문에 대시보드 전체가 백엔드를 기다리는 것을 막았다.

## 변경 내용 (What)

- `admin-dashboard-presenter.ts` — 카드 값을 뽑는 순수 계산
- `admin-metric-card.tsx` — props 만 받는 표현 컴포넌트
- `admin-dashboard-screen.tsx` — #93이 세운 껍데기를 채웠다

카드 셋:

| 카드 | 출처 | 보여주는 것 |
|---|---|---|
| AI 호출 | `fetchAdminAiCalls` ×2 | 총 건수 · 실패 건수 · 실패 비율 |
| 수집 상태 | `fetchAdminRefreshStatus` | 마지막 수집 시각 · 최신 고시일 · 통화쌍 수 · 거시지표 |
| 환율 결측 | `fetchAdminFxGaps` | 결측 영업일 · 미완전 통화쌍 |

### 카드마다 따로 부른다

한 번에 묶어 부르면 AI 집계가 죽었을 때 환율 상태까지 못 보게 된다. 카드마다 요청을 나눠
**하나가 실패해도 나머지는 그대로 선다**. 테스트로 고정했다.

### 호출 수를 프론트에서 더하지 않는다

AI 사용량 집계(`usage-summary`)에는 성공·실패 구분이 없다. 버킷을 더해 총계를 만드는 대신
호출 로그를 `size=1` 로 두 번 불러 서버가 센 `totalElements` 를 읽는다 — 한 번은 전체,
한 번은 `outcome=error`. 프론트가 세지 않는다.

### 실패 0건이 정상이라는 뜻은 아니다

`fallback(템플릿 대체)`을 함께 센다. 실 API 가 꺼져 있으면 모든 서술이 템플릿으로 나가고
`error` 는 0이다. **실패 건수만 보면 "정상"으로 읽히지만 LLM 은 한 번도 불리지 않았다.**
둘을 나란히 두고, 전부 템플릿이면 그 사실을 한 줄로 알린다.
(`admin-ai-call-vocabulary.ts` 가 "fallback 을 실패로 칠하지 않는다"고 이미 정해 둔 것과 같은 판단이다.)

### 서버가 아직 열지 않은 지표는 붉게 세우지 않는다

`GET /api/v1/admin/fx-rates/status` 는 프론트에 호출부만 있고 **백엔드에 없다**(백엔드 이슈 #128,
OPEN). 수집 상태 카드가 404 를 붉은 에러 패널로 세우면 진짜 장애와 구분이 되지 않는다.
`isAdminEndpointMissing` 으로 "없다"는 신호만 갈라 **"준비 중"** 으로 떨어뜨린다.
`admin-last-refresh-line.tsx` 가 쓰던 관례를 그대로 따랐다.

### 0으로 나눈 값을 0%로 적지 않는다

호출이 한 건도 없을 때 실패 비율을 `0.0%` 로 적으면 "실패가 없다"로 잘못 읽힌다.
분모가 0이거나 값을 모르면 대시로 남긴다.

## 영향 / 리스크

`/admin` 착지점은 #93 에서 이미 대시보드로 바뀌었다. 이 변경은 그 화면의 내용만 채운다.

AI 호출 카드가 요청을 두 번 보낸다. 집계만 필요하므로 `size=1` 이라 응답이 작다.

계산에 영향 없음 — 건수·시각·영업일 수는 모두 서버 값이고, 실패 비율만 표시용 파생이다.
