## 변경 사유 (Why)

사용자 화면 다섯 개가 모두 같은 방식으로 로딩을 처리하고 있었다.
`state.status === "loading"` 이면 화면 전체를 `ApiStateView` 한 장으로 갈아
치웠다. 가운데 스피너 하나에 문구 두 줄인 280px 카드다.

그래서 세 가지 문제가 있었다.

1. **화면이 통째로 사라진다.** 탭 바, 통화쌍 선택, "플래너 열기" 같은 이동
   버튼까지 전부 언마운트됐다. 무료 서버가 절전에서 깨는 데 최대 1분이
   걸리는데(`components/common/cold-start-banner.tsx`), 그동안 화면에는
   스피너 하나뿐이었다.
2. **방금 누른 컨트롤이 사라진다.** 환율 범위에서 통화쌍이나 기간을 바꾸면
   `use-forecast.ts` 가 무조건 `loading` 으로 되돌리고, 그러면 사용자가 방금
   클릭한 `ForecastControls` 가 화면에서 없어졌다.
3. **값이 도착할 때 화면이 튄다.** 280px 카드 하나가 다단 그리드로 바뀐다.

## 변경 내용 (What)

- `components/common/skeleton.tsx` + `skeleton.css` 추가. `line`·`block`·
  `circle` 세 모양의 자리표시자. 항상 `aria-hidden` 이다.
  - `line` 은 `inline-block` + `height: 0.75em` 이다. 인라인 요소는 부모의 줄
    상자에 참여하므로, 막대 높이가 `line-height` 보다 낮은 한 부모 높이는
    글자 한 줄이 있을 때와 같다. 값이 도착해도 주변이 밀리지 않는 이유다.
- `tokens.css` 에 `--skeleton-base` / `--skeleton-sheen` 추가. 기존 토큰의
  별칭이라 리터럴 색이 늘지 않는다. 라이트/다크에서 밝기 관계가 뒤집히므로
  두 토큰의 짝을 서로 바꿔 배정한다.
- 표현 컴포넌트가 데이터를 `T | null` 로 받는다. `null` 이면 값 자리만
  자리표시자가 되고 제목·라벨·버튼·표 머리글은 그대로 렌더된다.
- 화면 컨테이너는 더 이상 로딩으로 트리 전체를 막지 않는다. 에러·빈 상태는
  지금처럼 전체 화면 `ApiStateView` 를 쓴다.
- `ApiStateView` 의 `status` 를 `"error" | "empty"` 로 좁혔다. 이 변경 후
  `loading` 호출부가 0개가 됐다. `Spinner` 자체는 다른 호출부 6곳이 남아
  있으므로 그대로 둔다.
- 앱 부트스트랩 게이트는 `app/app-shell-skeleton.tsx` 로 바꿨다. 실제 셸과
  같은 클래스명을 써서 반응형 규칙을 그대로 물려받는다.

화면별로 로딩 중에도 살아 있는 것:

| 화면 | 살아 있는 컨트롤 |
|---|---|
| 환율 범위 | 통화쌍 select, 기간 칩 6개 (둘 다 정적 상수라 서버가 필요 없다) |
| 내 자산 | 서브 탭 2개, 적합도 탭의 통화 칩·비율 슬라이더 |
| 홈 | 통화쌍 select, 플래너 열기, 자산 등록/편집, 환율 범위 확인하기 |
| 마이페이지 | 바로가기 3개, 의사결정 프로필 카드(sessionStorage 기반) |
| 환전 계획 | 머리말, 데모로 둘러보기 |

## 영향 / 리스크

- **`useHomeMarket` 의 통화쌍 상태 처리가 바뀌었다.** 인자를 `useState` 초기값
  으로 받아 두면 늦게 온 홈 요약의 통화쌍이 반영되지 않는다. 사용자가 고른
  값만 상태로 들고, 고르기 전에는 인자를 그대로 쓰도록 바꿨다. 덕분에 홈
  요약을 기다리는 동안에도 통화쌍을 바꿔 시세를 먼저 받아 올 수 있다.
- **`XRayFitnessView` 의 시뮬레이터 통화 선택도 같은 이유로 파생값이 됐다.**
  로딩 중에는 주력 통화를 몰라 후보 목록에 그 통화가 섞여 있고, 값이 도착하면
  목록에서 빠진다. 저장한 선택이 더 이상 후보가 아니면 첫 후보로 돌아간다.
- **플래너의 '새 목표 만들기' 는 로딩 중 비활성이다.** 목록을 받기 전이라
  이미 있는 목표를 모른 채 같은 목표를 또 만들 수 있어서다. 버튼은 같은
  자리에 서 있고 누를 수만 없다.
- **부트스트랩 셸만 컨트롤이 살아 있지 않다.** 세션이 없는 구간이라
  `Sidebar` 가 요구하는 `accountKind` 가 없고, `Header` 가 품은
  `NotificationMenu` 는 토큰 없이 요청을 쏴 401을 받는다. 애초에 어디로
  이동해도 갈 곳이 없는 구간이다.
- `ModelScoreCard` 는 `score === null` 이 이미 '이 지평에는 성적표가 없다'는
  뜻이라 로딩을 null 로 나타낼 수 없다. 별도 `isLoading` 플래그를 뒀다.

## 롤백 방법

이 PR 을 revert 한다. `ApiStateView` 의 `status` 에 `"loading"` 이 돌아오고
각 화면의 조기 반환도 함께 되살아난다. 되돌려도 데이터 계약은 바뀌지 않는다.
