# 0059 — 대시보드 카드 배치를 다시 짜고, 추세선을 축이 있는 그래프로 바꾼다

- 이슈: #71
- 브랜치: `feat/dashboard-grid-layout`
- 유형: feat
- 작성일: 2026-09-08

## 왜

카드가 모두 같은 층위로 읽혀 무엇을 먼저 봐야 할지 드러나지 않았다. 배치를
정하기 전에 실측부터 했다(본문 984px 기준).

| 카드 | 변경 전 |
|---|---|
| 오늘의 시장 | 780 × 481 |
| 오늘의 핵심 | 480 × 227 |
| 내 외화 현황 | 480 × 268 |
| 내 목표 | 480 × 161 |

## 배치

```
3 3 3 3 3     ← 오늘의 핵심 (전폭, 얇은 띠)
1 1 1 4 4     ← 오늘의 시장  | 내 목표
1 1 1 2 2     ←              | 내 외화 현황
5 5 5 5 5     ← 경제 일정 (전폭)
```

`<768px` 1열 / `768~1023px` 2열 / `≥1024px` 5열. DOM 순서가 곧 모바일 읽기
순서이며 CSS로 순서를 바꾸지 않는다.

### 오늘의 핵심 — 카드에서 띠로 (227px → 75px)

그 카드가 담는 것은 문장 하나와 배지 몇 개뿐인데 984px 폭의 대부분이 비어
있었다. 가로로 눕혀 전폭 헤드라인 지위는 유지하면서 자리는 3분의 1로 줄였다.

### 오늘의 시장 — 3행이 아니라 2행

3행(약 704px)으로 만들면 폭은 24% 줄고 높이는 46% 늘어 아래쪽 200px가 빈다.
팬 차트를 넣으면 3행이 성립하지만 **환율 전망 화면과 같은 그림이 두 곳에
생기므로** 이번에는 넣지 않는다.

### 오른쪽 기둥을 한 칸으로 묶었다 — 카드 사이 여백의 원인

처음에는 목표·현황을 각각 그리드 행에 놓았는데 카드 **사이**에 39px씩 빈
공간이 생겼다.

```
grid-template-rows:  227 | 200 | 451 | 430
실제 카드 높이:            161   412
```

시장 카드가 `span 2`인데 오른쪽 두 카드의 합보다 78px 커서, 그리드가 남는
높이를 두 행에 39px씩 나눠 넣은 것이다. `align-items: start` 때문에 카드는 행
위쪽에 붙고 아래가 벌어진다.

**여백의 양이 아니라 위치가 문제다.** 마지막 카드 아래로 가면 페이지 여백으로
읽히지만 카드 사이에 끼면 "왜 떨어져 있지"가 된다. 오른쪽 두 카드를 한
칸(`__side`)에 묶어 그리드가 행을 나눌 일을 없앴다. 지금 카드 사이 간격은
정확히 `gap` 값(24px)이다.

## 추세선 → 축이 있는 그래프

스파크라인은 200×36 고정이라 카드에 비해 곁다리로 읽혔다. 카드 폭을 다 쓰는
꺾은선으로 바꾸고 세로축 3눈금·가로축 3눈금·옅은 눈금선을 붙였다.

`Sparkline` 은 삭제했다. 그 파일이 스스로를 "축·눈금·툴팁이 없는 **의도적으로
빈약한** 그림"으로 정의하고 있어 축을 붙이면 정체성과 충돌한다. 사용처가 이
카드 하나뿐이라 남겨 두면 죽은 코드가 된다. 대신
`components/common/trend-chart.tsx` 를 새로 두었다.

- 고정 픽셀이 아니라 `viewBox` 480×220 + `width: 100%` 라 카드 폭에 맞춰
  늘어나고 비율이 유지된다.
- 세로축은 하나다(개발 컨벤션 7.3, 듀얼 액스 금지).
- 값은 서버가 준 그대로만 그린다. 여기서 하는 계산은 좌표 환산뿐이다(§1).
- 축을 그리려면 날짜가 필요하므로 변환 계층이 환율만 뽑던 것을 관측점 통째로
  넘기도록 바꿨다(`sparklineRates` → `trendPoints`).

현재 환율 글자는 `clamp(2rem, 7vw, 3rem)` → `clamp(1.75rem, 4vw, 2.25rem)` 로
줄였다. 그래프와 자리를 나눠 갖게 하기 위해서다.

## 내 목표 — 마감 임박순 + 스크롤

서버는 목표를 **정렬도 개수 제한도 없이** 전부 내려준다
(`HomeSummaryService.resolveGoalsRoute`). 그대로 그리면 목표 수만큼 카드가
길어져 옆 카드와의 배치가 목표 개수에 따라 흔들린다.

- 경계에서 **마감 임박순**으로 세운다. 대시보드는 "오늘 무엇을 봐야 하는가"를
  답하는 화면이고 목표에서 그 답은 기한이다. 계산이 아니라 표시 순서라 §1과
  충돌하지 않으며, 원본을 뒤집지 않도록 복사해 정렬한다(§7.6).
- 목록에 최대 높이(약 3.5개, 264px)를 두고 넘치는 만큼은 스크롤로 담는다.
  반 칸이 잘려 보이는 것이 "아래에 더 있다"는 유일한 신호라 딱 떨어지는 값을
  쓰지 않는다.
- 스크롤 영역은 `tabIndex={0}` 과 `aria-label` 을 갖는다 — 마우스 없이도 훑을
  수 있어야 한다.

**순서는 서버가 정하는 편이 맞다.** 그래야 플래너와 대시보드가 같은 순서를
본다. divurve-api#154 로 요청해 두었다.

| 목표 수 | 변경 전 카드 높이 | 변경 후 |
|---|---|---|
| 1개 | 161px | 161px |
| 6개 | 약 540px | **373px** |
| 20개 | 약 1,600px | **373px** |

## 도넛 — 통화 4종부터 색이 무너진다

`toCurrencyColor` 는 USD·JPY·EUR 만 고정 배정이고 나머지는 전부
`--text-muted` 라 조각이 넷 이상이면 회색끼리 구분되지 않는다. 색을 늘리는
것은 통화 색 고정 배정 규칙(개발 컨벤션 7.2)과 충돌하므로 **상위 3개 +
"기타"** 로 묶는다. 라벨에 묶인 통화 수를 함께 적는다.

범례는 전부 나열한다 — 통화 코드가 글자로 붙어 있어 색이 같아도 읽히고,
정확한 금액은 그쪽이 유일한 출처다.

## 죽은 코드 제거

`HomeDashboardData.forecast`(`ForecastSummaryData` + `toForecast()`)를 지웠다.
매 렌더 객체를 만들지만 **어떤 화면도 읽지 않는다** — `home-dashboard-view` 는
`today`·`profileFit`·`asOfLabel`·`fxStatus`·`goalsRoute`·`attention` 만 쓴다.
UI 개편 때 시장 카드가 `HomeMarketSnapshot` 경로로 옮겨 가며 남은 잔해이고,
테스트가 커버리지 100% 를 채우고 있어 살아 있는 코드처럼 보였다.

그것을 지우자 `home-presenter.toRateLabel` 도 아무도 쓰지 않게 됐는데, 확인해
보니 `forecast-presenter.ts` 에 **글자 하나 다르지 않은 같은 함수**가 있었다.
홈 쪽을 지워 복제가 사라졌다(0058 의 `toPercent` 통합과 같은 종류다).

  때는 드러나지 않는 문제였다.
