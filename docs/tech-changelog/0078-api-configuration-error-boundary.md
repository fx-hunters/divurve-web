## 변경 사유 (Why)

수정 worktree의 5173 서버에서 홈 진입이 실패했다. 이 worktree에는
`.env.example`만 있고 실행 중인 Vite의 환경에 `VITE_API_URL`이 없었다.
원본 작업 폴더의 Git 무시 파일은 새 worktree에 자동으로 포함되지 않는다.

`apiUrl()`의 설정 오류가 `fetch`와 같은 try/catch 안에서 처리되면서
`NETWORK_ERROR`로 바뀌고 절전 안내까지 활성화됐다. 실제 API 요청은 0건인데
서버 연결 실패와 서버를 깨우는 중이라는 두 문구가 함께 나왔다.

## 변경 내용 (What)

- 주소 검증을 인증 갱신, 요청 지연 타이머, 실제 fetch보다 먼저 수행한다.
- 주소 누락을 `ApiError`의 `API_CONFIGURATION_ERROR`로 구분한다.
  오류를 표시하는 기존 세션 UI는 설정을 확인하라는 메시지를 그대로 사용한다.
- 설정 오류에서 fetch를 호출하지 않고 절전 안내를 켜지 않는 회귀 테스트를 추가한다.
- 로컬 실행 환경은 원본 폴더의 기존 API 주소 항목 하나로 복원했다.
  `.env.local`은 Git 무시 대상이며 커밋하지 않는다. 원본 설정, 인증정보,
  Vite 프록시, backend 및 배포 설정은 수정하지 않았다.

## 영향 / 리스크

인증·401 refresh·응답 변환·Planner 금융 수치와 저장 정책은 변경하지 않는다.
API 실패를 fixture 성공으로 바꾸지 않는다. 실제 fetch 실패와 지연에서 동작하는
기존 배너 정책도 유지한다. 이 배너는 응답 지연에 대한 안내이며 서버 절전의
측정 결과가 아니다. 잘못된 주소, CORS, 실제 네트워크 문제의 포괄적인 진단 UI는
이번 변경에 추가하지 않았다.

## 검증

- 수정 전 새 회귀 테스트 실패: 설정 누락이 `NETWORK_ERROR`로 반환됐다.
- 수정 후 client·auth·session-bootstrap·cold-start-notice·App: 5파일, 95테스트 통과.
- 실제 localhost 브라우저에서 데모 인증 POST와 홈 GET이 200으로 응답했다.
  대시보드 → 플래너 → 일본 목표 Curve → 같은 탭 새로고침 후 재진입을 확인했다.
- 실제 모듈에 빈 API 주소를 전달한 검수에서도 설정 오류가 반환됐고 배너는 꺼져 있었다.
- 데모 인증 이외의 서버 쓰기, 관리자 접근, AI 유료 호출은 실행하지 않았다.
  AI 요청은 감사 브라우저에서 차단했으며 이 차단 오류를 서버 장애로 판정하지 않는다.
- 전체 coverage: 137파일, 1,190테스트 통과. Statements·Branches·Functions·Lines 100%.
  관련 테스트 뒤 최종 전체 게이트를 1회 실행했으며 coverage 기준을 변경하지 않았다.
- `npm run lint`: 오류 0, 기존 Fast Refresh 경고 17개, 종료 0.
- `npm run build`의 TypeScript 검사와 Vite 빌드 성공. 814모듈, JS 930.98kB.
  기존 500kB 번들 경고가 남으며 기준을 완화하지 않았다.
- `git diff --check`: 통과. 환경 파일·개인 검수 보고서는 스테이징하지 않는다.

## 롤백 방법

이 수정 커밋만 revert하면 이전 오류 분류로 돌아간다. 이는 주소 누락을 해결하지 않으며
실제 로컬 연결은 각 worktree의 실행 환경 설정이 필요하다. 원본 worktree의 설정과
기존 사용자 파일을 삭제하거나 복원 명령으로 덮어쓰지 않는다.
