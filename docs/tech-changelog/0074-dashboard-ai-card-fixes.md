## 변경 사유 (Why)

PR #104 로 대시보드에 카드 넷을 더한 뒤 처음으로 화면을 실제로 띄워 봤다. 두 가지가
드러났다.

### 1. 토큰 추이 카드가 400을 받는다 (#107)

차트 자리에 `VALIDATION_FAILED / status 400 / field from` 이 떠 있었다. 원인이 두 겹이다.

**형식.** `GET /admin/ai/usage-summary` 는 `from`·`to` 를 `Instant` 로 받는다.

```java
@RequestParam(value = "from", required = false)
@DateTimeFormat(iso = DateTimeFormat.ISO.DATE_TIME) Instant from
```

카드는 `2026-09-02` 처럼 **날짜만** 보냈다.

**기준 시간대.** 이쪽이 더 나쁘다. 카드가 `toDefaultFxRateRange` 를 썼는데 그것은
환율 화면용이고 **Asia/Seoul** 기준으로 날짜를 끊는다. 그런데 집계 응답의 `day` 는
**UTC** 로 잘려서 온다. `admin-ai-call-query.ts` 의 파일 주석이 정확히 이 함정을
경고해 두었는데, 그것을 읽지 않고 환율용 헬퍼를 끌어다 썼다.

형식만 고쳤다면 400 은 사라지고 **x축 날짜가 9시간 어긋난 채** 그려졌을 것이다.
에러가 사라져 고쳐진 것처럼 보이는 쪽이 더 위험했다.

### 2. AI 카드 둘이 같은 숫자를 찍고 있었다 (#108)

`AI 호출` 카드와 `AI 결과 분해` 카드가 나란히 서서 똑같이 `301건` 을 찍었다.
뒤엣것이 앞엣것의 상위 집합이었다.

| AI 호출 카드 | 결과 분해 카드에서 나오는 값 |
|---|---|
| 301건 | 301건 (같은 값) |
| 실패 0건 | `error` + `quota_blocked` |
| 템플릿 대체 14건 | `fallback` |
| 실패 비율 0.0% | 위 값에서 계산 |

`AI 호출` 카드에만 있던 정보는 실패 비율 하나이고 그것도 파생값이다. 만든 순서
탓이다 — `AI 호출` 은 #84 에서, `결과 분해` 는 #101 에서 나왔고 붙이면서 겹치는지
확인하지 않았다. 대시보드에서 같은 숫자가 두 번 찍히면 보는 사람이 "둘이 왜
다른가" 를 먼저 의심하게 된다.

## 변경 내용 (What)

- `cards/ai-token-trend-card.tsx` — 기간 계산을 `toDefaultFxRateRange`(서울, 날짜)
  에서 `toDefaultAiCallRange` + `toUtcRangeStart`/`toUtcRangeEnd`(UTC, ISO datetime)
  로 바꿨다. AI 호출 로그 화면이 쓰던 것을 그대로 쓴다 — 새로 만든 함수는 없다.
- `cards/ai-outcome-card.tsx` — 실패 비율 한 줄과 `isAllFallback` 경고를 받았다.
  `error > 0` 일 때의 경고색도 이 카드로 옮겼다.
- `cards/ai-card.tsx` — 지웠다.
- `admin-dashboard-screen.tsx` — 카드가 일곱에서 여섯으로 줄었다.

## 영향 / 리스크

**기본 조회 기간이 바뀐다.** 한 달에서 7일로 줄어든다. AI 호출 로그 화면과 같은
기간이 되어, 두 화면을 오갈 때 같은 구간을 보게 된다.

| | 변경 전 | 변경 후 |
|---|---|---|
| 기준 시간대 | Asia/Seoul | UTC |
| 보내는 형식 | `2026-09-02` | `2026-09-02T00:00:00Z` |
| 기간 | 1개월 | 7일 |
| 결과 | 400 | 차트 |

대시보드에서 없어진 정보는 없다. `AI 호출` 카드의 네 값이 모두 결과 분해 카드에
있거나 그 안에서 계산된다.
